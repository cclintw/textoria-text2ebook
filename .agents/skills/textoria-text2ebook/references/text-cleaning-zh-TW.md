# 編碼、擷取與文本清理

## 清理範圍

```text
轉碼、擷取、清理或重新清理前必讀。
目前 CLI 使用 cc_text_cleaner；沒有可選的保守清理設定。
```

## 保存來源與工作文本

```text
逐一檢查輸入，製書時保存來源副本。
新集合工作文本 = content/全文.md。
既有舊集合才沿用 clean/cleaned_text.md；依 file-contracts-zh-TW.md。
一般製書 → UTF-8 準備與擷取 Markdown 留在記憶體。
明確轉碼任務 → 寫 prepared/<stem>.utf8.<ext>。
明確擷取任務 → 寫 intermediate/plain_text.md。
階段紀錄 → 寫 state.json；一般建置不另增轉碼／擷取報告。
既有人工修改文本 → 不自動重新清理。
來源位元組或選項改變且將覆寫工作文本 → 先取得明確重新清理決定。
清理完成不代表章節已確認。
```

## 解碼與正規化

```text
實作 = textoria_utf8_converter.py。
嚴格嘗試順序 = UTF-8 BOM／UTF-8 → Big5-HKSCS → Big5 → Shift JIS → GB2312。
均失敗 → 諮詢 charset-normalizer → 最後回退 Big5。
Big5 解碼優先 HKSCS。
嚴格解碼成功不保證語意正確辨識；可疑文本仍需檢查。
正規化：
  CRLF／CR → LF。
  移除 BOM 字元與指定控制字元。
  Unicode replacement character → ■。
  套用 NFKC。
NFKC 也影響稍後受保護行中的相容字元與標點。
保留原始檔供比較。
不宣稱可偵測或還原所有私用字、亂碼；目前不自動重建原字形。
```

## 依格式擷取

| 格式 | 處理 |
|---|---|
| TXT／Markdown | 以準備後文本作為工作串流。 |
| HTML／HTM | 移除 script/style/head/svg/nav、註解；擷取標題、段落、清單、引文、表格、圖片參照。 |
| CSV | 必須以 `--text-column` 指定存在欄位；依列序用空行連接非空值。 |

```text
HTML 輸出 = Markdown 標題、簡單清單／引文、首列後有分隔列的表格、圖片參照。
行內文字扁平化；不保證原連結目標、豐富樣式、任意巢狀標記與細緻排版。
不宣稱完整保真轉換或全面消毒所有 URL。
書目試算表另行處理；CSV 正文欄位不是書目匯入。
不支援正文輸入 = XML/XHTML、PDF、DOCX、圖片 OCR。
```

## 清理文本

實作：`textoria_clean_text.py`。

| 輸入 | 輸出 |
|---|---|
| `﹃`／`﹄` | `『`／`』` |
| `﹁`／`﹂` | `「`／`」` |
| `︿`／`﹀` | `〈`／`〉` |
| `︽`／`︾` | `《`／`》` |

```text
一般正文行：
  依 HALFWIDTH_PUNCT 轉換逗號、句號、冒號、括號、方括號、斜線等 ASCII 標點。
  直雙引號在每行內交替轉為開／閉直角引號；彎雙引號轉直角引號。
  移除半形空白與 tab，僅保留 ASCII 字母／數字之間的一個空白。
  移除行尾空白、合併過多空行；結果以一個換行結尾。
不做正文標點／空白轉換的行：
  圍欄程式碼、Markdown 標題、管線表格、註腳定義、含 Markdown 圖片語法的行。
上述保護不豁免先前正規化，不代表位元組保真的 Markdown 往返。
禁止默默增加 = 繁簡轉換、刪註腳或頁面附屬文字、修復歷史標點。
不宣稱所有字面標記都會被辨識為損壞。
```

## 記錄並轉交審閱

```text
記錄 = 所選設定、偵測編碼、正規化、規則、字元／行統計、標記數量。
紀錄是處理診斷，不證明每個字元正確。
僅在影響下一項決策時呈現具體問題；保留來源供比較。
下一步 = 章節審閱，不直接生成最終成果。
```
